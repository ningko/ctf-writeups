> **!!!** the flag for this challenge is barely even hidden, so I don't think it's much of an issue to include it.

**site:** picoCTF

**Statement**

> Our server seems to be leaking pieces of a secret flag in its logs. The parts are scattered and sometimes repeated. Can you reconstruct the original flag? Download the [logs](https://challenge-files.picoctf.net/c_amiable_citadel/49cec6157142f24a599f4164d5b63322c2494f801390d6f22eb91b3aa592bc66/server.log) and figure out the full flag from the fragments.

---

The *logs* are just one long file (`server.log`) where the very first line is this:

```console
$ cat server.log   
[1990-08-09 10:00:10] INFO FLAGPART: picoCTF{us3_
```

To get the full flag, I wrote a python script to extract each line's flag parts and add them all together:

```console
with open('./flagparts.txt', 'r') as file:
    data = [line.rstrip('\n') for line in file]

arr = []

for element in data:
    segment = element.split()
    part = segment[4]
    arr.append(part)

arr = list(dict.fromkeys(arr))
flag = ''.join(x for x in arr)
print(flag)
```

So this:
- Opens the file I created earlier, separates each new line and adds them to an empty list (`data`)
- Iterates through every "`element`" (line) in that list and separates it in parts (for example, in the line "`[1990-08-09 10:05:54] INFO FLAGPART: sk1lls_`", the `part` we're interested in would be `segment[4]`, since that's the index `skills_` is at, which will be saved to the `part` var)
- Each `part` gets added to a list (`arr`), which is then filtered to get only the unique values in it (`list(dict.fromkeys(arr))`), because the flag parts are duplicated and out of order. These unique values are then added to an empty string (`flag`) for easy printing.

Running this scripts results in:

```console
$ python3 script.py                 
picoCTF{us3_y0urlinux_sk1lls_cedfa5fb}
```
